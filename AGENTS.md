# Правила для ИИ-агента

GitHub является главным источником правды проекта.

1. Перед работой проверь remote и синхронизируйся с origin/main.
2. Не меняй main напрямую для заметных изменений.
3. Создай отдельную feature-ветку.
4. Изучи PROJECT.md, TASKS.md, README.md и историю последних изменений.
5. Делай небольшие изменения с понятным результатом.
6. После законченного блока сделай понятный commit.
7. Перед push запусти доступные локальные проверки.
8. После push создай Pull Request.
9. Проверь GitHub Actions.
10. Merge в main только после успешных проверок.
11. После merge убедись, что origin/main содержит итог.
12. Не проси пользователя выполнять Git-команды вручную, если у тебя есть Git/GitHub.
13. Не коммить `.env`, токены, ключи, сессии, пароли и другие секреты.
14. Если пользователь открывает новый чат, сначала восстанови фактический контекст из GitHub, а не полагайся на память разговора.
15. Не говори «готово» без доказательства: commit/PR/checks/main или другого фактического результата.

## GitHub CLI (gh) - основной интерфейс ИИ к GitHub

Если gh доступен, используй его как основной интерфейс к GitHub вместо просьб пользователю кликать по интерфейсу.

Перед GitHub-операциями:
1. Проверь наличие gh.
2. Если gh отсутствует, установи официальный GitHub CLI подходящим для текущей ОС способом.
3. Проверь авторизацию через gh auth status.
4. Если авторизации нет, попроси пользователя только пройти безопасный browser/device login. Не проси токен в обычном чате.
5. После авторизации настрой Git credential helper через gh auth setup-git, если это нужно текущей среде.
6. Никогда не используй gh auth token или gh auth status --show-token без доказанной технической необходимости. Не печатай токены.

Через gh сам выполняй:
- создание и просмотр репозиториев;
- создание и просмотр Pull Request;
- просмотр diff и checks;
- ожидание GitHub Actions;
- merge после зелёных checks;
- Issues и Projects, если они нужны;
- Releases;
- просмотр workflow и runs;
- создание GitHub Secrets безопасным способом, если secret действительно нужен Actions.

На Mac и VPS GitHub CLI должен работать одинаково с точки зрения процесса: ИИ управляет GitHub, пользователь подтверждает только неизбежную авторизацию.

Если текущая версия gh поддерживает официальный agent skill и он реально улучшит работу coding agent, можешь предложить или установить официальный skill gh в пользовательском scope. Не делай это обязательным условием работы.

## Pull Request Template

Файл .github/pull_request_template.md является стандартом проекта.

При каждом заметном PR:
- используй шаблон;
- заполни все разделы фактическими данными;
- не оставляй формальные галочки без проверки;
- обязательно укажи, как проверялся результат;
- обязательно проверь отсутствие секретов;
- merge только после успешных GitHub Actions.
